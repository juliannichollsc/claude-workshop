Agente LM

Tiene herramientas (leer, escribir, ejecutar) y un loop: actúa, observa el resultado, corrige.

Claude Code = Claude + terminal + filesystem + git + el loop

El loop del agente

Todo lo que hace Claude Code
cabe en 4 pasos

01

Contexto

Lee tu prompt, CLAUDE.md, archivos, salidas previas. Todo entra a la ventana.

02

Decisión

Elige la siguiente herramienta: ReadEditBash

03

Acción

Ejecuta de verdad: escribe archivos, corre pnpm build, lanza subagentes.

04

Observación

El resultado —incluido el error— vuelve al contexto. Y el loop se repite.

Por eso un error de compilación no es un fracaso: es la observación que cierra el ciclo.

Contexto

La ventana de contexto es
la memoria de trabajo

  • Es todo lo que el modelo “ve” en un turno: system prompt, CLAUDE.md, tu mensaje, archivos leídos, salidas de tools.
  • No es una base de datos. Es volátil, finita y costosa.
  • Si algo no está en el contexto, para el modelo no existe.
  • Si sobra basura, el modelo se distrae: peor calidad, más tokens, más lento.

Tokens

La unidad de todo: el token

~4

caracteres por token en inglés. En español, algo menos.

1M

tokens de ventana en los modelos largos de Opus.

5 min

de caché. Repetir contexto pronto es barato; tarde, no.

Barato

input cacheado Leer el mismo archivo dos veces seguidas. Reusar CLAUDE.md.

Caro

outputthinking Generar código, razonar largo, volcar archivos enteros al chat.

Regla práctica: carga poco, apunta bien. Un Grep preciso vale más que 10 Read completos.

Context engineering

4 reglas que cambian el resultado

01

Escribe CLAUDE.md

Es el contexto que siempre está. Convenciones, stack, reglas duras. Corto y mandatorio.

02

Compacta a tiempo

/clear entre tareas independientes. Un contexto sucio arrastra decisiones viejas.

03

Delega a subagentes

Cada subagente tiene su propia ventana. Explora en la suya, te devuelve la conclusión.

04

Carga bajo demanda

Las Skills solo entran cuando aplican. Progressive disclosure, no un manual entero.

Parte 03 · Prompt 2

Agentes y Skills

Especialización, aislamiento y conocimiento reutilizable

Skills

Una Skill es conocimiento,
no una acción

  • Un SKILL.md con frontmatter: name + description.
  • La description es lo único siempre cargado. Es el “cuándo usarme”.
  • El cuerpo entra solo al invocarse: progressive disclosure.
  • Puede traer scripts/, assets/, references/.
  • Esta presentación se generó con la skill html-slides
--- .claude/skills/three-fiber-scroll.md name: three-fiber-scroll description: | Patrón para integrar un modelo 3D con scroll usando ScrollControls + useScroll de drei. Use this skill when se necesita configurar la integración entre el scroll del SPA y el modelo 3D. --- # Three Fiber + Scroll Pattern useFrame(() => { ref.current.rotation.x = scroll.offset * Math.PI * 2 }) ## Reglas críticas - useFrame NUNCA llama setState - Cada sección = h-screen - Siempre useGLTF.preload()
Agentes

Un agente es una ventana propia
+ un rol + herramientas limitadas

orchestrator

No escribe código. Descompone, delega, verifica compatibilidad. Todo pasa por él.

technical-agent

canvas/ data/ types/ hooks/ — Three.js, R3F, scroll, tipos.
ReadWriteEditBash

ui-agent

sections/ ui/ — Tailwind, GSAP, layout responsive.
ReadWriteEdit (sin Bash)

qa-agent

Nunca modifica código. Lee, ejecuta checks, reporta al orchestrator.
ReadBashGrep

El campo tools del frontmatter no es una sugerencia: es una cárcel. qa-agent físicamente no puede escribir.

Anatomía

El description es el router

--- .claude/agents/ui-agent.md name: ui-agent description: | Construye componentes React con Tailwind, animaciones GSAP ScrollTrigger, layout responsive. Use this agent when se necesita crear o modificar componentes visuales HTML. <example> user: "Crea las cards de skills" assistant: "Construiré SkillsSection.tsx con glassmorphism y entrada staggered." </example> model: inherit color: magenta tools: ["Read", "Write", "Edit", "Glob", "Grep"] --- Eres el agente de UI/UX... **Archivos que NUNCA tocas:** canvas/, data/
  • Los <example> importan. Es cómo el orchestrator aprende a enrutar.
  • “Archivos que NUNCA tocas” en el system prompt del agente, no solo en CLAUDE.md.
  • Los patrones de código van dentro del agente: el GSAP boilerplate, el useFrame.
  • Troubleshooting conocido ahorra ciclos: “modelo negro → falta Environment”.
CLAUDE.md

La regla que lo amarra todo

## REGLA OBLIGATORIA Todas las tareas de desarrollo DEBEN pasar por el agente orchestrator. NUNCA ejecutes tareas directamente — siempre delega: ui-agent → todo lo visual technical-agent → todo lo técnico (3D, hooks, tipos) qa-agent → verificación (build, responsive, perf)

CLAUDE.md entra en cada turno. Por eso: corto, imperativo, sin relleno. Cada línea que agregas la pagas en todos los prompts del proyecto.

El prompt

Y cuánto quieres que Claude piense

Anatomía de un prompt

5 piezas. Ninguna opcional.

01 · CONTEXTO
Dónde estás parado
“Estoy en un proyecto React + Three.js ya inicializado.”
02 · TAREA
Un verbo, un objetivo
“Configura toda la capa de agentes, skills y CLAUDE.md.”
03 · RESTRICCIONES
Lo que NO debe hacer
“No modifiques ningún archivo de src/ en este paso.”
04 · FORMATO
Cómo se ve el output
Bloques de código literales, rutas exactas, interfaces completas.
05 · VERIFICACIÓN
Cómo sabe que terminó
“Ejecuta pnpm build y corrige hasta que compile limpio.”
model & effort

Dos perillas que casi nadie toca

model

Qué cerebro corre la tarea. En un agente: model: inherit hereda el de la sesión.

ModeloPara
Opus 4.8Arquitectura, orquestación
Sonnet 5Implementación diaria
Haiku 4.5Tareas mecánicas, alto volumen

effort

Cuánto razona antes de actuar. Más effort = más tokens de thinking = más lento y caro.

NivelCuándo
lowRenombrar, formatear, mover
mediumFeature acotada — el default
highBug sutil, diseño de API
maxRefactor grande, race condition

Anti-patrón: max effort para todo. Quemas tokens y contexto sin ganar precisión en tareas triviales.

La animación

Dos motores. Nunca se cruzan.

3D → useFrame (R3F)

const scroll = useScroll() const ref = useRef<THREE.Group>(null) useFrame(() => { if (!ref.current) return // solo eje X, 0 → 2π ref.current.rotation.x = scroll.offset * Math.PI * 2 }) // NUNCA setState aquí dentro

DOM → GSAP ScrollTrigger

useGSAP(() => { gsap.from('.animate-item', { y: 60, opacity: 0, duration: 0.8, stagger: 0.1, ease: 'power3.out', scrollTrigger: { trigger: containerRef.current, start: 'top 80%', }, }) }, { scope: containerRef })

Regla dura del CLAUDE.md: GSAP jamás anima objetos Three.js. useFrame jamás toca el DOM. Cruzarlos es el bug #1 de este stack.

Para llevar

Lo que quiero que recuerden

  • El contexto es finito y volátil. Cárgalo con intención, límpialo sin culpa.
  • Un buen prompt trae contexto, tarea, restricciones, formato y verificación.
  • Una Skill es conocimiento reutilizable. Un agente es una ventana aislada con un rol.
  • La separación de archivos es lo que hace que varios agentes no se pisen.
  • model y effort son perillas reales: ajústalas a la tarea, no al miedo.
  • El agente no adivina: le das el loop y le das cómo verificar. El resto lo hace él.
